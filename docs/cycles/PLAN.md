# `exp/rc-server-mode` — Remote Control JSON-RPC server parity work

Branch: `exp/rc-server-mode`, base = `main` @ `655b128`.

Cycle IDs are **semantic**, not numeric. Each cycle has its own directory
under `docs/cycles/<id>/` and ends with a commit on this branch.

Constraints (these are project-wide rules; check `AGENTS.md`):

- **No `go test ./...`** — only `go test ./cmd/... ./internal/...`.
- **Don't reformat pre-existing `gofmt` dirt** (50+ files in `internal/` + a
  handful in `cmd/wagyu`). Only format files you add or fully rewrite in a
  cycle.
- **Don't push unless asked.**
- **Don't probe `/logout` or `/exit`** in print mode; other slash commands
  are fair game; `/keybindings` is rejected in print mode.
- **Cycle IDs must not collide with numbered ones** (no `cycle-N` strings
  in this branch; we deliberately drop the `cycle-` prefix to avoid the
  next sibling's number).
- **WebSocket library = `github.com/coder/websocket` v1.8.x**. Not
  `gorilla/websocket`. Not `nhooyr.io/websocket`. Not `net/http` hand-rolled
  upgrade (coder does the upgrade + framing right, including ping/pong/close
  semantics + a context-aware `Read` / `Write` API).

## Goal

Bring `wagyu`'s `--remote-control` daemon up to **functional parity** with
`agy`'s `Remote Control`: a JSON-RPC-over-WebSocket server that an external
frontend can drive end-to-end (start a cascade, send messages, receive
streaming state updates, list models/slash-commands/projects/etc.).

What "parity" means here:

- **Wire protocol**: JSON-RPC 2.0 over WebSocket on `/rpc`, listening on a
  TCP address bound to `0.0.0.0` (not just loopback), same `jsonrpc` /
  `method` / `params` / `id` envelope as `agy`.
- **Method surface**: the **same method names** as `agy`'s
  `RemoteAgent*` / `remoteControl*` decompiled functions, with the same
  parameter shapes. (Names from `out/local-macos/dec/`:
  `StartRemoteAgentCascade`, `SendRemoteAgentCascadeMessage`,
  `StreamRemoteAgentStateUpdates`, `HandleRemoteAgentCascadeUserInteraction`,
  `ListRemoteAgentModels`, `ListRemoteAgentSlashCommands`,
  `ListRemoteAgentConversations`, `ListRemoteAgentEnvironments`,
  `ListRemoteAgentProjects`, `CreateRemoteAgentProject`,
  `UpdateRemoteAgentProject`, `ReadRemoteAgentFile`, `ReadRemoteAgentDir`,
  `DeleteRemoteAgentMessage`, `DeleteRemoteAgentConversation`,
  `EnsureRemoteAgentACEVM`, `RemoteAgentErrorStatus`,
  `SetRemoteControlSession`, `RemoteControlStatus`, etc.)
- **Daemon lifecycle**: `remote-control start` actually spawns + registers a
  persistent daemon (LaunchAgent on macOS, so we match the Linux systemd
  shape but defer it until there's evidence). `--session` keeps it
  login-scoped.
- **ADC story**: keep the 1.3.3 rule (refuse `--remote-control` +
  `$AGY_ADC_AUTH`) for now; `rc-auth-adc` later can lift it once OAuth is
  real.

What it does **not** mean:

- Byte-exact wire frames. `agy`'s RPC envelopes are internal; parity is by
  method-name + param-shape, not bit-for-bit.
- All ~30 methods fully implemented on day 1 — we ship them in the order
  below, with a method returning a parseable "not yet implemented" envelope
  if a client calls one earlier than expected.

## Architectural direction

- Replace the in-process Unix-socket daemon (`internal/remotecontrol/`)
  with a **long-running daemon process** spawned by
  `wagyu remote-control start`. The `internal/remotecontrol/` package
  becomes the **shared library** that the daemon process and the CLI both
  import (the CLI uses it to wire `--remote-control` for the per-turn
  variant).
- Transport layer: a thin `internal/remotetransport/` package around
  `coder/websocket` (with `http.Server` + `http.ServeMux` + `WsHandler`).
  Two listeners: TCP (default for `remote-control start`, the
  custom-frontend target) and Unix-socket (kept for the per-turn
  `--remote-control` in TUI/print paths — local PIDs only).
- JSON-RPC: server side lives in `internal/remotecontrol/` (or split off
  into `internal/jsonrpcserver/` later if it grows). The dispatcher maps
  method names → handler funcs; we register handlers in cycles as we ship
  them.
- PiG plumbing: `internal/pigrt/runtime.go` already does
  `coding.Session.Send` with an event drain. For `rc-cascade-message` /
  `rc-cascade-stream`, we wrap that as a `*Cascade` value in the daemon:
  one PiG session per ws connection (agy uses one cascade per
  `StartRemoteAgentCascade` call, we mirror).
- Auth: deferred. The handshake accepts a `clientInfo` only. A real
  token-based handshake is `rc-auth-tokens` after the rest is stable.

## Sub-agent protocol

Each cycle is driven by **one focused general-purpose sub-agent** that:

1. Reads this `PLAN.md` row for the cycle.
2. Inspects the **relevant agy decompiled files** under
   `out/local-macos/dec/` on the **main worktree** (`openagy`, NOT this
   worktree — the decompile dir is huge and lives in main). Reports
   return the absolute path the sub-agent cites.
3. Looks at the reference CHANGELOG:
   `cmd/wagyu/testdata/print_changelog.md` (canonical) and
   `internal/cli/testdata/changelog_reference.txt` (recovery).
4. Implements in **this worktree** (`/Users/gear/Documents/GitHub/openagy-rc`).
5. Runs `go build ./...` + `go test ./cmd/... ./internal/...` until green.
6. Writes a `docs/cycles/<id>/deliverable.md` report that follows the
   style of existing reports (`docs/cycles/cycle-216/` is the most recent
   example — bilingual zh-CN/EN, ends with 硬约束 / limitations).
7. Commits the cycle with a message of the form
   `<verb>(<scope>): <short> (<id>)`.
8. Reports back to the orchestrator with:
   - commit hash
   - files added / modified / removed
   - test count and coverage delta (run inside this worktree)
   - report path
   - any 硬约束 / caveats

The orchestrator verifies the commit, then launches the next cycle's
sub-agent with a brief that includes the just-completed cycle's hash.

## Conventions enforced

- `go.mod` adds `github.com/coder/websocket v1.8.15` (direct dep, not
  indirect).
- Cycle reports land at `docs/cycles/<id>/deliverable.md`; never at
  `docs/cycles/cycle-<n>/`.
- Commit messages don't carry `cycle-N` strings.
- The worktree's branch is **never merged into main** from a sub-agent;
  merging is the orchestrator's job.
- Pre-existing `gofmt` dirt stays put. The sub-agent formats only files it
  added or fully rewrote.

## Project-wide 硬约束 (verification patterns future cycles must use)

These are bugs / mis-uses that have happened at least once on this branch. Listed so future cycles don't repeat them.

### `wc -l | awk '$1 > N'` is a **trap**, not a check

`find … | xargs wc -l` prints a final row of `<sum> total` where `<sum>` is the sum of every file's line count. `awk '$1 > N'` matches that bogus row because `<sum> > N` is trivially true. The result is a false-positive count of "1 file > N" with `<sum>` as the "line count" — a confident-looking lie.

**Correct verification pattern** (filters out the `total` line):

```bash
find <pkg> -type f -name '*.go' -not -name '*_test.go' | \
  xargs wc -l 2>/dev/null | grep -v ' total$' | awk '$1 > N'
```

Or use `find … -exec wc -l {} + | grep -v ' total$'` which produces the same shape.

**Bug history**: during `rc-filesize-internal-remotecontrol` verification, the orchestrator ran `awk '$1 > 500'` against the `xargs wc -l` output and reported "0 violations" multiple times without noticing the script was wrong. Only a direct user prompt ("你注意历史提交了吗，又一个 500 行文件限制，你改的这些文件满足约束吗") caught it. The actual data was correct (commit `d5ea66e` etc.); only the display was lying.
