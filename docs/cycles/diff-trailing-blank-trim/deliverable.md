## What was implemented

The fix is a **display normalisation** at the seam between `git` output
and the inline-diff subview's renderer. The clone never touches the file
on disk — only the string it puts on screen.

### Seam

`cmd/wagyu/slash_viewer_panels.go::gitDiffBody` is the single point where
`git diff --no-color -- <path>` / `git show --no-color <hash>` text
becomes data lines the inline-diff subview (`panelDiffInlineLines`)
consumes. Before this commit, `gitDiffBody` returned `strings.Split(out,
"\n")` verbatim; now it applies `trimDiffTrailing(l)` to each element of
the slice before returning.

### Helper

`cmd/wagyu/slash_diff_trim.go::trimDiffTrailing(line string) string`:

```go
return strings.TrimRight(line, " \t")
```

`U+0020` and `U+0009` are the two whitespace runes git emits at the tail
of a diff content line when the on-disk line had trailing spaces or
tabs. `\r` is deliberately left untouched: the gap specifically calls
out trailing tabs/spaces, and `git --no-color` on macOS produces LF line
endings so CRLF-in-the-tail is a corner case for the autocrlf=input
workflow, not a default. The leading marker byte is preserved by
construction — `TrimRight` only touches the suffix.

### Where the trim is *not* applied

- The chrome of the /diff viewer (tab row, no-VCS warning, "no diff
  available" placeholder, legend `panelDotHint`, the `←/→ switch view`,
  `↑/↓/j/k navigate`, `enter view diff`, `esc dismiss` strings) is
  generated by code, not by `git` — there is no concept of "trailing
  whitespace" to strip from those rows, and they are SGR-coloured control
  rows whose exact byte sequence is pinned by the cycle-207/226 tests.
- The `diffAllChangesRow` / `diffAllChangesLines` list-view rows build
  their own strings (`" M <path>  +A -D"` etc.) — same reason.
- All other viewers in the cycle (`/usage`, `/changelog`, `/codesearch`,
  `/skills`, `/plugin`, `/tasks`, etc.) operate on text that has its own
  preprocessing pipeline that already drops trailing whitespace on the
  way in. The diff viewer is the unique case where the raw byte stream
  hit the renderer untouched.

### The `runGit` interaction

`runGit` still does `strings.TrimRight(string(out), "\n")`, removing only
the trailing newline git emits. My new `trimDiffTrailing` runs *after*
that, on each line of the already-line-stripped output. No interaction
with the existing LC_ALL=C/PAGER=cat/GIT_PAGER=cat env.

## Tests added

| Name | Covers gap requirement |
|---|---|
| `TestDiffTrimTrailingTab` | trailing tab trimmed (single, multiple, header) |
| `TestDiffTrimTrailingSpace` | trailing space trimmed (single, multiple, indent preserved) |
| `TestDiffTrimPreservesInternalWhitespace` | internal whitespace kept untouched |
| `TestDiffTrimBlankLinePreserved` | empty line stays empty; whitespace-only → empty |
| `TestDiffTrimPlusMarkerNotTrimmed` | leading `+` survives marker-only and marker-with-trail cases |
| `TestDiffTrimMinusMarkerNotTrimmed` | leading `-` survives the same |
| `TestDiffTrimHunkHeaderPreserved` | `@@ ... @@` byte-identical when no trailing whitespace |
| `TestDiffTrimFileHeaderPreserved` | `diff --git`, `index`, `--- a/`, `+++ b/`, `new file mode` byte-identical |
| `TestDiffTrimEndToEndRealRepo` | end-to-end with real git: dirty file with trailing tab renders `+line WITH TRAILING TAB` (no trailing tab) |

`TestDiffTrimEndToEndRealRepo` is the one integration test:
1. `git init`, commit `line without tabs\n`.
2. Overwrite with `line without tabs\nline WITH TRAILING TAB\t\n`.
3. Open `/diff`, hit Enter on `tab.txt`, capture `panelDiffInlineLines`
   output, strip SGR, assert (a) the trimmed form
   `+line WITH TRAILING TAB` appears, and (b) every match has no trailing
   tab/whitespace beyond the marker.

The test is skipped when `git` is not on PATH, matching the convention
used by `TestCycle226*` tests in the same package.

## 硬约束 / Not verified

- **Display comparison against REF 1.4.0 with a real trailing-tab file**
  was not run against `~/.local/bin/agy` directly. The integration test
  in this commit uses a synthetic git repo and asserts on the cloned
  renderer's output. End-to-end parity with REF would require capturing
  `~/.local/bin/agy`'s `/diff` output for the same input, which is out
  of scope for a single-cycle subagent task.
- **Visual side-by-side diff** (REF 1.4.0's real layout, not the
  cycle-226 `panelDiffInlineLines` substitute) is **not** the path this
  fix targets. The clone's inline subview calls `gitDiffBody`; a
  future side-by-side renderer, if/when it lands, will also feed off
  `gitDiffBody` and inherit the trim automatically.
- **CRLF line endings in the tail**: deliberately left alone. A
  Windows-style `\r` at the end of a diff content line is not trimmed.
  This matches the gap description ("trailing tabs/spaces") and avoids
  changing behaviour for files checked in under `core.autocrlf=input`.
- **`TestDispatchPrintSlash_LocalCommands`** in `print_slash_test.go`
  fails on `main` and on this branch with the same message
  (`expected "minimax-m3\tMiniMax M3"`, got `"gemini-3.8-flash-medium…"`).
  This is a pre-existing failure unrelated to the /diff path; `git log`
  confirms it is not introduced by this commit. The targeted regex
  `TestDiff|TestTrail|TestRender` does **not** match it, so the
  cycle's smoke run stays green.
- **`TestCycle225QuotaCountdown`** is a 1-minute boundary flake
  (`59m1s` → expects `"59m 0s"`); passes when run alone and 5/5 in
  repeat. Pre-existing flakiness, not touched by this commit.
