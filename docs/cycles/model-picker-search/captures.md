# Cycle `model-picker-search` — the evidence

Everything here was recorded live on this machine (macOS/arm64) against

| binary | version | how it was driven |
|---|---|---|
| `~/.local/bin/agy` | Antigravity CLI **1.4.5** | tmux pane, `tmux capture-pane -e -p` |
| `/tmp/wagyu` (this clone) | cycle `model-picker-search` | tmux pane, `--backend shim` (no network) |

The raw captures are **not** committed (they are regenerated by the scripts
in `repro/`); the transcripts below are what was read out of them.

---

## 1. The reference's picker, byte for byte

`repro/wg02_reference_model_picker.sh` — the reference with no query:

```
Switch Model

> Gemini 3.8 Flash             (current)
  Claude Sonnet 4.6 (Thinking)
  Claude Opus 4.6 (Thinking)
  GPT-OSS 120B (Medium)

  Effort  ◂        ●━━━━━━━━━━━━━━●━━━━━━━━━━━━━━◉        ▸

```

Raw (`capture-pane -e`), the three lines that matter:

```
  Search: ^[[7m^[[37m ^[[0m
          ^[[38;5;254m────────────────────
```

The search box is a **reverse-video cell** (`\x1b[7m\x1b[37m \x1b[0m`) — the
same constant the clone already had (`searchCursorBlock`), and the
underline is 20 `─` in 256-colour 254 (the clone's truecolor
`#EEE8D5` degrades to exactly that).

## 2. The search filters as you type 【一手】

| query | rows the reference shows | order |
|---|---|---|
| `claude` | Claude Opus 4.6 (Thinking), Claude Sonnet 4.6 (Thinking) | Opus, Sonnet |
| `s` | Claude Sonnet 4.6 (Thinking), Gemini 3.8 Flash, GPT-OSS 120B (Medium), Claude Opus 4.6 (Thinking) | Sonnet, Flash, GPT-OSS, Opus |
| `clauson` | Claude Sonnet 4.6 (Thinking) | — |
| `cl-opus` | *nothing* | — |
| `zzz` | *nothing* | — |
| `j` | *nothing* | — |

Three facts fall out of that table:

1. **The match is a subsequence, not a substring.** `clauson` is not a
   substring of `Claude Sonnet 4.6 (Thinking)` but matches it.
2. **The match is against the display label only.** `cl-opus` is a
   subsequence of the catalogue id `claude-opus-4-6-thinking` and of
   nothing else — and it matches nothing.
3. **A printable key filters; it does not navigate.** `j` went into the
   box (`Search: j`) and the cursor did not move. The reference's legend
   says `↑/↓ Navigate` — the letters are not navigation keys here.

The order is query-dependent (`claude` → Opus first, `s` → Sonnet first),
so the reference sorts by *relevance*, not by catalogue order. See §5.

## 3. The empty-result line, byte for byte 【一手】

```
^[[39m  ^[[38;5;60mNo models match "zzz"^[[39m

^[[1mKeyboard: ^[[0m^[[38;5;32mesc^[[39m ^[[38;5;66mClear search^[[39m
```

Two leading spaces, the message in 256-colour 60, and a legend that
collapses to `esc Clear search` alone — no `↑/↓ Navigate`, no `enter
Select`. The legend's last entry changes with the state:

```
esc Go Back          ← the search box is empty
esc Clear search     ← a query is live
```

## 4. Esc clears the query and keeps the panel open 【一手】

With `Search: zzz` live, Esc returns the panel to the full list and the
legend back to `esc Go Back`. A *second* Esc closes the panel. This is the
one place where the clone's behaviour changed: Esc used to close the panel
unconditionally.

## 5. The relevance order, as measured

Nine queries were run against the reference and the order recorded. A
single rule reproduces all nine:

1. a row the user **cannot select** (the dim `Gemini 4 Argon`) sorts
   **last**, even though its label is the shortest;
2. then the rows whose match lands on a **word boundary** (the first
   character, or one preceded by a space) — more is better;
3. then the **shorter label**;
4. then the earlier first match.

| query | predicted | reference | ✓ |
|---|---|---|---|
| `c` | Opus, Sonnet | Opus, Sonnet | ✓ |
| `claude` | Opus, Sonnet | Opus, Sonnet | ✓ |
| `clauson` | Sonnet | Sonnet | ✓ |
| `4.6` | Opus, Sonnet | Opus, Sonnet | ✓ |
| `4` | Opus, Sonnet, Argon | Opus, Sonnet, Argon | ✓ |
| `gemini` | Flash, Argon | Flash, Argon | ✓ |
| `thinking` | Opus, Sonnet | Opus, Sonnet | ✓ |
| `s` | Sonnet, Flash, GPT-OSS, Opus | Sonnet, Flash, GPT-OSS, Opus | ✓ |
| `g` | Flash, GPT-OSS, Opus, Sonnet, Argon | Flash, GPT-OSS, Opus, Sonnet, Argon | ✓ |

The `s` row is the one that pins the rule down: `Claude Sonnet 4.6
(Thinking)` wins because its `S` starts a word, and the remaining three
come out by label length (16, 21, 26). `GPT-OSS 120B (Medium)` has a
*doubled* `SS` but it does not start a word, and the reference still puts
it after the shorter `Gemini 3.8 Flash` — so a consecutive match does not
outrank a shorter label.

The exact score function of the reference was **not** recovered; the rule
above is a documented approximation that reproduces every observed case.

## 6. The clone, before and after

### Before — the seventh row was unreachable 【一手】

`cmd/wagyu/slash_panel_routing.go` counted the picker's rows with a
hard-coded `6`:

```go
case panelModel:
	return 6
```

The picker draws five reference rows plus the configured ones, so with two
configured models the seventh row (`MiniMax M3.1 Flash`) could not be
reached — eight presses of ↓ left the cursor on the sixth:

### Byte diff, clone vs reference 【一手】

The two panes were captured with the same terminal (256-colour) and the
same query, and the panel region was diffed:

```
$ diff <(reference) <(clone)        # query "claude"
4c4
<           [38;5;254m────────────────────
---
>           [38;5;254m────────────────────[39m
```

That is the **only** difference, and it is the trailing reset the clone
emits after the underline — a pre-existing difference in the shared
`searchUnderline` constant, invisible on screen (the underline is the
last coloured span on its line). The reference does not reset there; it
resets at the *start* of the next coloured span instead, which is why its
empty-result line begins with `^[[39m`.

The clone's emitted bytes for that line are identical to the reference's
(`\x1b[39m  \x1b[38;5;60mNo models match "…" \x1b[39m`); tmux does not
re-emit the leading reset in the capture because the clone's underline
already reset the foreground.

## 7. The provider type that broke the wrapper 【一手】

The clone's own legacy flat configuration wrote a *provider type* named
`agw` into `~/.config/openagy/models.json`:

```json
{
  "name": "minimax-m3.1-flash",
  "display_name": "MiniMax M3.1 Flash",
  "provider": "agw",
  "api_key": "-",
  "api_url": "https://agw.k0s.io/v1/chat/completions"
}
```

The rename of that type to the generic names (`d780f075`) dropped `agw`
from `models.NewProvider`'s switch, so the flat file stopped loading:

```
provider: models: unknown provider "agw"
```

That string is what the reference printed over the wrapper's proxy
(`⚠ Bad Gateway (code 502): provider: models: unknown provider "agw"`)
and what left the TUI generating forever.

The endpoint itself is fine — a direct probe of the user's configuration
answers 200:

```
$ curl -sS -m 25 -o /tmp/agw_probe.txt -w "HTTP %{http_code}\n" \
    -X POST https://agw.k0s.io/v1/chat/completions \
    -H "content-type: application/json" -H "Authorization: Bearer -" \
    -d '{"model":"MiniMax-M3","messages":[{"role":"user","content":"ping"}],"max_tokens":16}'
HTTP 200
{"id":"0729db3f6fb07affffdf47107ae29626","choices":[{"finish_reason":"length","index":0,
 "message":{"content":"<think>We need answer likely pong. Could be casual. \"pong\" perhaps with</think>\n\n",…
```

After the alias, the same configuration works end to end:

```
$ /tmp/wagyu -p "reply with the single word: pong" --model minimax-m3.1-flash
pong

$ /tmp/agy-wrapper -p "reply with the single word: pong" --model "MiniMax M3.1 Flash"
pong
```

and the wrapper's own TUI answers through the model it advertises:

```
> reply with the single word: pong
  pong
```

## 8. Reproducing

```sh
# the clone's picker (offline, fixture configuration)
docs/cycles/model-picker-search/repro/wg01_model_picker.sh /tmp/wagyu ./captures

# the reference's picker (live: the machine's credentials are used)
docs/cycles/model-picker-search/repro/wg02_reference_model_picker.sh ~/.local/bin/agy ./captures
```

The reference script waits for the panel instead of for a fixed delay —
the reference fetches the model catalogue over the network first, and a
fixed delay races with it.
